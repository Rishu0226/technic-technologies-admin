# ADMIN PANEL IMPLEMENTATION PLAN
# TECHNIC TECHNOLOGIES

This document outlines the strict execution plan for building the `technic-technologies-admin` project.

## 1. Architecture & Boundaries
- **Strict Separation**: The Admin Panel will not contain any MongoDB connection strings, Mongoose models, or database queries.
- **API Communication**: The Admin Panel will interact exclusively with the Backend via RESTful APIs using a centralized `lib/api.ts` axios/fetch wrapper.
- **Tech Stack**: Next.js 14/15 App Router, React, Tailwind CSS, Lucide React, React Hook Form.

## 2. Design System
The Admin Panel will adopt the existing Technic Technologies visual identity (Dark theme, glassmorphism, glowing gradients, modern typography) but optimized for a high-density, professional SaaS Dashboard layout. 
- **Layout**: Fixed sidebar on desktop (collapsible drawer on mobile), top header with user profile, and main content area.
- **Components**: Glass cards for metrics, data tables with subtle borders, glowing buttons for primary actions, and custom form inputs.

## 5. API Integration & Authentication
- **Centralized Client**: `lib/api.ts` will be configured with `NEXT_PUBLIC_API_URL`.
- **Credentials**: The client will send `withCredentials: true` to pass the HTTP-only JWT cookie generated by the Backend on successful login.
- **Interceptors**: Global error handling to catch `401 Unauthorized` responses and cleanly redirect the user to `/admin/login`.
- **Secrets**: No backend secrets (e.g., `JWT_SECRET`, `MONGODB_URI`) will exist in the Admin Panel.

## 6. Key Features Implementation Details

### A. Dynamic Career Experience Options
The Career form (`/admin/careers/create` and `edit`) will include a dynamic array builder for `experienceOptions`. The admin can add strings like "0-2 Years", "2-4 Years". The frontend application form will dynamically render these as a dropdown selection.

### B. Dynamic Application Fields Builder
A dedicated component (`DynamicFieldBuilder.tsx`) will be built into the Career forms. It will allow the admin to define an array of `applicationFields` objects containing:
- `name` (e.g., "Full Name")
- `type` (e.g., "text", "email", "file")
- `required` (boolean)

### C. Services & Products Management
When creating or editing Services and Products, the `icon` field will be a simple string input (e.g., "Bot", "Cloud", "Code"). The Admin Panel will not store or send React components.

### D. Table Management & Validation
- **Tables**: Every list view will use a reusable `DataTable` component supporting Search, Pagination, Loading (Skeleton UI), and Empty states.
- **Forms**: Managed via `react-hook-form` with client-side validation. Submit buttons will feature `disabled` and `saving...` states to prevent duplicate API calls.
- **Deletions**: Guarded by a `ConfirmDialog` component to prevent accidental data loss.
